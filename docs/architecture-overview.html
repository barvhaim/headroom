Headroom · architecture

A local proxy that makes Claude Code
send fewer tokens upstream

Headroom sits on localhost between your coding agent and an Anthropic-compatible gateway. It compresses the bulky parts of each request — tool outputs, logs, large context — while treating the prompt cache as sacred. Nothing leaves the machine except the LLM traffic itself.

▲

Your Anthropic-compatible gateway → Claude models

Receives a smaller request. The cached prefix arrives byte-identical, so the prompt cache still hits. SSE response streams back through the proxy untouched.

The whole design rests on one idea. Compression is not "drop old messages from history" — that would bust the prompt cache on every turn. Instead: the cache hot zone (system prompt, tools, old turns, reasoning/thinking blocks) is never touched. Only the freshest turn — the live zone — is compressed, type-aware and position-preserving.

Key subsystems

Live-zone compressor

Walks messages from the tail, isolates the latest user content & tool results, dispatches each block to a type-specific compressor, and edits bytes in place.

  • SmartCrusher — JSON / structured
  • LogCompressor — verbose logs
  • DiffCompressor — patches
  • SearchCompressor — grep/find output
  • Kompress — plain text (ONNX)

CCR · compress-cache-retrieve

Compression is reversible. Dropped bytes are hash-keyed and stored; a headroom_retrieve tool is registered so the model can pull the full content back if it actually needs it.

Tokenizer & validation

Every compression is checked with a real tokenizer (HF / tiktoken). If it wouldn't shrink the token count, the original is forwarded — compression can never make a request bigger.

Auth-mode policy

Headers classify the client as PAYG, OAuth, or subscription. PAYG gets aggressive compression; OAuth/subscription prefer lossless passthrough and avoid any fingerprint-altering header rewrites.

TOIN observability

Tool-Output Intelligence Network watches patterns across requests to tune compressors — strictly observe-only. It never alters a live request's decision; recommendations are published between deploys.

Endpoints & metrics

/livez · /readyz health, /stats for tokens saved, plus Prometheus metrics and a built-in dashboard. Multi-provider handlers: Anthropic, OpenAI, Gemini, Bedrock/Vertex.

The cache-safety invariants

Every transform in the pipeline is held to these rules. They are what keep the prompt cache hitting while still shrinking the payload.

I1
Byte-faithful passthrough. Bytes sent upstream are SHA-256-equal to bytes received — except the ranges a transform deliberately changed. No re-serialization, no whitespace drift.
I2
Cache hot zone never modified. system, tools, any message before frozen_message_count, and all reasoning/thinking/redacted/compaction blocks are immutable.
I3
Append-only. Once a message has gone upstream, its bytes are frozen forever. Compression touches only the newest turn.
I4
Deterministic. Same (bytes, frozen_count, auth_mode) → byte-equal output. No timestamps, no random seeds.
I5
Token-aware, not byte-aware. Validated against a tokenizer; if it doesn't reduce tokens, the original is forwarded.
I6
Position-preserving. Never reorders, splits, or adds inline fields to a block. CCR directives ride in a separate sibling marker block.

Two-language implementation

Headroom is mid-migration: a mature Python proxy is being progressively re-implemented as a faster Rust core, behind the same wire contract and invariants.

Python — headroom/

The running proxy today

FastAPI server, per-provider handlers, ContentRouter, CCR, memory, dashboard, CLI wrappers, evals. Calls into the Rust core for hot-path compression.

Rust — crates/

The performance core

headroom-core (tokenizer, smart_crusher, ccr, auth_mode, cache_control), headroom-proxy (axum), exposed to Python via headroom-py / maturin as _core.so.

The phased plan — passthrough lockdown → live-zone engine → Rust SSE parser → Bedrock/Vertex native → cache stabilization → auth policy → Python retirement — lives in REALIGNMENT/.
